# 環境固有値の一覧

自宅 PC で構築した環境を別の環境（組織の Hyper-V など）で再現する際に、**確認・変更が必要になる値**の一覧です。

「設定ファイルに外出しして汎用化する」のではなく、**どこを変えれば動くかを明示する**方針です。再現が目的の段階では、こちらの方が把握しやすく確実です。

---

## 前提：組織で再現する際の方針

| 項目 | 自宅環境 | 組織環境（想定） |
|---|---|---|
| 仮想化基盤 | Hyper-V | Hyper-V（同じ） |
| ゲスト OS | Windows 11 | Windows 11（同じ。将来 Windows Server 2022） |
| ドメイン | `plm-lab.local` | **`plm-lab.local`（同じものを使う）** |
| 開発環境 | VS2026 + .NET 10 → 4.8 | **VS2019 + .NET Framework 4.8（推奨）** |

**ドメイン名を変えない方針**であれば、変更箇所は大きく減ります。証明書・SP の設定・IdP のメタデータをそのまま流用できるためです。

> **推奨**：組織では**最初から VS2019 で再現**してください。最終目標が VS2019 である以上、VS2026 で再現してから移行するのは二度手間になります。また、VS2019 で開けない問題があれば初期段階で発覚する方が安全です。

---

## 1. 変更が不要な値（ドメインを変えない場合）

以下はそのまま流用できます。**変更しないことで再現の手間が大きく減ります。**

| 値 | 内容 |
|---|---|
| ドメイン | `plm-lab.local` |
| SP ホスト名 | `sp.plm-lab.local` |
| IdP ホスト名 | `idp.plm-lab.local` |
| IdP ポート | `8443` |
| LDAP ポート | `10389` |
| LDAP ベース DN | `dc=example,dc=com` |
| 利用者 | `01PLM01` / `01PLM02`（Joe アカウント） |
| LDAP 検索用アカウント | `uid=idp-reader,ou=people,dc=example,dc=com` |
| アプリケーションのパス | `/PLM` |
| JWT の Issuer / Audience | `PlmSsoDemo` / `PlmSmartClient` |
| 資格情報の名前 | `PlmSsoDemo/JwtSigningKey` |

## 3. 証明書について

**最も手間がかかる部分**です。証明書は環境ごとに作り直すのが原則です。

| 証明書 | 用途 | 再現時の扱い |
|---|---|---|
| ルート CA（`PLM-Lab Root CA`） | 内部 CA | **新規作成**を推奨。または自宅の CA 証明書＋秘密鍵を持ち込む |
| SP のサーバ証明書（`sp.plm-lab.local`） | IIS の HTTPS | ルート CA から新規発行 |
| IdP の証明書（`idp.plm-lab.local`） | Tomcat の HTTPS | 同上 |
| IdP の署名・暗号化証明書 | SAML アサーション | **IdP の再構築時に自動生成される** |
| ClickOnce の署名証明書 | マニフェスト署名 | VS が自動生成する仮証明書で可（検証段階） |

> ⚠️ **IdP の証明書を作り直すと、SP 側のメタデータも更新が必要**です。IdP と SP は互いの証明書を信頼関係の根拠にしているため、片方だけ作り直すと SSO が成立しません。**IdP のメタデータを再取得して SP に配置し直す**手順を忘れないでください。

## 4. 設定ファイル別の確認箇所

### `hosts`（`C:\Windows\System32\drivers\etc\hosts`）

```
<仮想マシンのIP>  sp.plm-lab.local
<仮想マシンのIP>  idp.plm-lab.local
```

同一マシン内で完結する場合は `127.0.0.1` でも構いません。別 PC からアクセスする場合は、そのマシンの `hosts` にも同じ設定が必要です。

### `shibboleth2.xml`

| 項目 | 確認内容 |
|---|---|
| `<Site id="1" name="sp.plm-lab.local" .../>` | **IIS のサイト ID と一致しているか**。既存サイトがあると ID が 1 以外になる |
| `<Host name="sp.plm-lab.local" ...>` | ホスト名 |
| `<Path name="PLM">` 配下の除外設定 | `api` と `smartclient` の除外（フェーズ2で確定） |
| IdP のメタデータの場所 | ファイルパスまたは URL |
| SP の署名・暗号化鍵 | 再作成した場合はパスを確認 |

### `Web.config`（`PlmSsoDemo.Web`）

| 設定 | 確認内容 |
|---|---|
| `JwtSigningKeyTarget` | 資格情報の名前（変更不要） |
| `JwtSigningKey` | **存在しないこと**（フェーズ4で削除済み） |
| `DevRemoteUser` | **コメントアウトされていること**（有効だと SSO を経由せず動いてしまう） |
| `DiagEnabled` | 確認中は `true`、確認後は `false` |
| `LogEnabled` | `true`（切り分けに有用） |

### IIS の構成

| 項目 | 設定値 |
|---|---|
| サイトのバインド | `https` / 443 / 証明書 `sp.plm-lab.local` |
| アプリケーション `/PLM` | 物理パス＝`PlmSsoDemo.Web` フォルダ |
| 仮想ディレクトリ `/PLM/smartclient` | 物理パス＝ClickOnce の発行先 |
| アプリケーションプール | .NET CLR v4.0 / 統合 / **ID＝資格情報を登録したアカウント** / **ユーザープロファイルの読み込み＝True** |
| MIME の種類 | `.application` / `.manifest` / `.deploy` |
| 認証 | 匿名認証のみ有効（Windows 認証は不要） |

### ClickOnce の発行設定

| 項目 | 設定値 |
|---|---|
| インストール URL | `https://sp.plm-lab.local/PLM/smartclient/` |
| 発行場所 | ClickOnce の発行先フォルダ（＝仮想ディレクトリの物理パス） |
| インストールモード | **オンラインのみ**（必須） |
| マニフェスト | ☑ **URL パラメーターをアプリケーションに渡すことを許可する**（必須） |

### フォルダのアクセス権

| フォルダ | 必要な権限 |
|---|---|
| `PlmSsoDemo.Web`（ソース） | `IIS_IUSRS` に読み取りと実行 |
| `PlmSsoDemo.Web\App_Data` | `IIS_IUSRS` に**書き込み** |
| ClickOnce の発行先 | `IIS_IUSRS` に読み取りと実行 |

## 5. SmartClient のコード内の値

`Program.cs` に、接続先の既定値がハードコードされています。

```csharp
private const string DefaultBaseUrl = "https://sp.plm-lab.local/PLM";
```

**ClickOnce 経由で起動する場合は、起動 URL から自動判定される**ため、この値は使われません。**VS でデバッグ実行する場合のみ**参照されます。ドメインを変えない限り、変更は不要です。

## 6. 再現時のチェックリスト

順に確認していけば、漏れなく再現できます。

- [ ] Hyper-V に Windows 11 の仮想マシンを作成（スリープ無効化）
- [ ] `hosts` に `sp.plm-lab.local` / `idp.plm-lab.local` を登録
- [ ] ルート CA を作成し、サーバ証明書を発行
- [ ] ルート CA を「信頼されたルート証明機関」に登録
- [ ] ApacheDS を導入し、利用者（`01PLM01` 等）とグループを作成
- [ ] Tomcat ＋ Shibboleth IdP を導入（8443 で HTTPS）
- [ ] IIS を導入（**ASP.NET 4.8 を有効化**）
- [ ] Shibboleth SP を導入し、IdP とメタデータを交換
- [ ] SSO の疎通確認（`whoami.asp` 等）
- [ ] Visual Studio を準備（**.NET Framework project and item templates** を追加）
- [ ] ソース一式を配置し、ビルド
- [ ] IIS にアプリケーションと仮想ディレクトリを作成、権限を設定
- [ ] `shibboleth2.xml` に `/PLM` 配下の除外設定を追加
- [ ] アプリケーションプールの ID とユーザープロファイル読み込みを設定
- [ ] 資格情報マネージャーに署名鍵を登録（**そのアカウントで実行**）
- [ ] ClickOnce を発行
- [ ] 動作確認（下記）

### 動作確認の項目

- [ ] `https://sp.plm-lab.local/PLM/Default.aspx` … SSO 経由で REMOTE_USER が表示される
- [ ] `https://sp.plm-lab.local/PLM/api/ping` … リダイレクトされずに JSON が返る
- [ ] `https://sp.plm-lab.local/PLM/api/diag` … 署名鍵の取得元が資格情報マネージャー
- [ ] 「SmartClient を起動」… パスワード入力なしで JWT 交換・API 呼び出しが成功
- [ ] SmartClient の `user` が、ブラウザ画面の REMOTE_USER と一致
- [ ] 引換券の再利用・トークン無し・改ざんが、いずれも 401

| 分類 | 内容 |

> **署名鍵は持ち込まないでください。** 環境ごとに新規生成するのが原則です（フェーズ4のスクリプトで生成できます）。

> **`bin` / `obj` / `.vs` / `packages` フォルダは不要**です。ビルド時に再生成されます。NuGet パッケージは復元されるため、ネットワーク制限がある場合のみ持ち込みを検討してください。
