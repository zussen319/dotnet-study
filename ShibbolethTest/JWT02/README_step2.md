# JWT 認証デモ ― ステップ2：クライアント（SmartClient 役）

ステップ1で作ったサーバに対して、**トークン取得 → API 呼び出し**をプログラムで自動的に行うコンソールアプリです。
これまで PowerShell で手動でやっていたことを、C# のクライアントが行います。実際の SmartClient
（ダウンロードされて動くクライアントアプリが Web サービスと通信する）の動きに近づけたものです。

## 前提

- **ステップ1のサーバ（JwtDemoServer）が起動していること**（`http://localhost:5000`）。
- サーバを先に起動し、そのまま**別ウィンドウ**でこのクライアントを実行します。

## 実行方法

### コマンドラインの場合

サーバを起動したまま、別のターミナルで：

```powershell
cd JwtDemoClient
dotnet run
```

### Visual Studio 2026 の場合

- サーバ（JwtDemoServer）を起動しておく。
- 別途 `JwtDemoClient.csproj` を開いて実行（コンソールアプリなので、実行するとコンソールウィンドウに結果が出ます）。
- ※ 2つのプロジェクトを1つのソリューションにまとめ、「複数のスタートアッププロジェクト」でサーバとクライアントを同時起動する設定も可能ですが、まずは別々に起動するのが分かりやすいです。

## 実行すると何が起きるか

コンソールに、次の流れが順に表示されます。

```
[1] トークンを取得します（POST /token）
  → 取得成功。JWT の先頭: eyJhbGciOiJIUzI1NiIsInR5cCI6...

[2] トークンを付けて保護 API を呼びます（GET /api/whoami）
        → 成功 (200)。username = 01PLM01

[3] 検証が効いていることを確認します
  (3-a) トークン無しで呼ぶ → 401 になるはず
        → 拒否 (401 Unauthorized)
  (3-b) 改ざんしたトークンで呼ぶ → 401 になるはず
        → 拒否 (401 Unauthorized)
  (3-c) 間違ったパスワードでトークン取得 → 発行されないはず
        → トークンは発行されなかった（期待どおり）
```

つまり、**1回の実行で「発行 → 検証成功 → 各種拒否」まで一通り**を、プログラムから確認できます。

## コードの見どころ（Program.cs）

- **(1) トークン取得**：`http.PostAsJsonAsync("/token", new { username, password })` … ユーザー名/パスワードを JSON で送り、返ってきた `access_token` を取り出す。認証失敗（401）なら `null` を返す。
- **(2) API 呼び出し**：`req.Headers.Authorization = new AuthenticationHeaderValue("Bearer", token)` … これが「トークンをリクエストに添える」部分。SmartClient が毎回やること。
- **(3) 拒否の確認**：トークン無し／改ざん／誤パスワードで、それぞれ 401・発行なしになることを確認。**サーバ側の検証が効いている証拠**。

## 実際の SmartClient との対応

| デモ | 実際の SmartClient |
|---|---|
| `GetTokenAsync` でトークン取得 | 初回に認証してトークンをもらう |
| トークンをメモリに保持 | クライアントがトークンを保持（有効期限まで使い回す） |
| `Authorization: Bearer` を付けて呼ぶ | 毎リクエストにトークンを添える |
| 401 が返る | トークンが無効なら再取得（or ログイン画面へ） |

## 発展のヒント（このあと相談しながら）

- **トークンの使い回し**：今は毎回取得しているが、実際は「一度取得 → 有効期限まで使い回す → 切れたら再取得」。この制御を足すとより実践的。
- **有効期限切れの体験**：トークン取得後に 5 分待ってから (2) を呼ぶと 401 になる。再取得のロジックを入れて自動回復させる、という発展ができる。
- **LDAP 認証への差し替え（ステップ4）**：サーバの `/token` を、固定ユーザーではなく ApacheDS（LDAP）に問い合わせる形に変える。01PLM01 の LDAP パスワードでトークンが取れるようになり、SSO 環境と統合される。
