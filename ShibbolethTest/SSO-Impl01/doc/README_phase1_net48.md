# フェーズ1：ClickOnce 引数受け取りスパイク（.NET Framework 4.8 版）

実装フェーズの**最初の作業**です。目的をひとつに絞ります。

> **ブラウザのリンクから ClickOnce アプリを起動したとき、URL に付けた `?ticket=XXXX` がアプリに届くか。**

ここが成立するかどうかで、以降の設計（SSO からの引換券の渡し方）が変わります。SSO も JWT もまだ扱いません。**最小のアプリで、この一点だけを先に確定させます。**

> ⚠️ **本フェーズは提案版です。** 実行して判明した点は、これまで同様この冒頭に追記して確定版にしてください。

---

## .NET Framework 4.8 を採用する理由（前提の再確認）

組織・顧客環境に合わせ、この段階から **.NET Framework 4.8 / C#** を対象にします。

- **VS2019 では .NET 10 のプロジェクトをビルドできない**（VS2019 が扱えるのは .NET 5 まで）
- **顧客サーバーに新しいランタイム依存を持ち込まない**（4.8 は Windows 同梱）
- **.aspx（WebForms）は 4.8 でしか動かない**ため、どのみち Web 側は 4.8 確定

**ClickOnce の観点では、4.8 の方がむしろ有利です。** .NET 7 以降の環境変数方式ではなく、`ApplicationDeployment.CurrentDeployment.ActivationUri` という長年使われてきた標準 API が使えます。

### 言語バージョンについて

組織の VS2019 でもビルドできるよう、**C# 7.3 の範囲**で記述しています（null 許容参照型・switch 式・範囲演算子などは使いません）。プロジェクト作成後、念のため次を設定しておくと事故を防げます。

プロジェクトのプロパティ →「ビルド」→「詳細設定」→「言語バージョン」を **C# 7.3** に。

## 成果物

| ファイル | 内容 |
|---|---|
| `Program.cs` | 起動情報を表示するだけの WinForms アプリ（4.8 / C# 7.3） |
| `launch-test.html` | 起動リンクを並べたテストページ |

`.csproj` は同梱していません。.NET Framework のプロジェクトは旧形式で記述量が多く、**Visual Studio のテンプレートから生成する方が確実**なためです。手順は下記のとおりです。

---

## 手順

### 1. プロジェクトを作る

Visual Studio 2026 で新規プロジェクトを作成します。

- テンプレート：「**Windows フォーム アプリ (.NET Framework)**」（C#）
  - ※「Windows フォーム アプリ」（.NET 用）と紛らわしいので注意。**(.NET Framework) と付いている方**を選びます。
  - テンプレートが一覧に出てこない場合は、Visual Studio インストーラーの「個別のコンポーネント」で **.NET Framework 4.8 のターゲットパック／SDK** と、旧 .NET テンプレートを追加してください。
- プロジェクト名：`SpikeClickOnce`
- フレームワーク：**.NET Framework 4.8**

生成された `Form1.cs`（および `Form1.Designer.cs`・`Form1.resx`）を**削除**し、`Program.cs` を本フォルダのもので置き換えます。フォームはコードで組み立てるため、デザイナーファイルは不要です。

### 2. 参照を追加する（重要）

ソリューションエクスプローラーの「参照」を右クリック →「参照の追加」→「アセンブリ」タブから、次を追加します。

- **`System.Deployment`** … `ApplicationDeployment` クラスを使うために必須

これが無いとビルドが通りません。

### 3. デバッグ実行で引数の受け取りを確認する

プロジェクトのプロパティ →「デバッグ」→「コマンドライン引数」に次を入力します。

```
--ticket=TESTTICKET
```

F5 で実行し、`ticket = TESTTICKET`（コマンドライン引数）と表示されれば OK です。

**これは同時に、ご要望(7)「VS 上でのデバッグ実行」の SmartClient 側の答え**でもあります。VS 実行時は ClickOnce 起動ではないため、引数で代用する形になります。

### 4. ClickOnce として発行する

プロジェクトのプロパティ →「**発行**」タブを開きます（.NET Framework では従来の発行ウィザードです）。

| 項目 | 設定値 | 理由 |
|---|---|---|
| 発行場所 | ローカルフォルダ（例：`C:\publish\smartclient\`） | 後で IIS に配置 |
| インストール URL | `https://plmdev.plm-lab.local/smartclient/` | 実際に配布する URL |
| インストールモード | **「このアプリケーションはオンラインでのみ利用可能にする」** | 毎回 URL 経由で起動させるため |

**そして最重要の設定**です。「**オプション**」ボタン →「**マニフェスト**」を選び、

- ☑ **「URL パラメーターをアプリケーションに渡すことを許可する」**（`TrustUrlParameters`）
- ☐ 「URL からのアプリケーションのアクティブ化をブロックする」は**オフのまま**

にします。**ここにチェックを入れないと `ActivationUri` は常に空**になり、ticket は絶対に届きません。

設定したら「今すぐ発行」を実行します。発行フォルダに `SpikeClickOnce.application`（配置マニフェスト）、`setup.exe`、`Application Files\` が生成されます。

> **インストールモードが「オンラインのみ」である理由**：インストール型にすると、利用者は初回だけ URL から起動し、以降はスタートメニューのショートカットから起動するため、クエリ文字列を受け取れるのは実質一度きりになります。毎回 SSO 経由で引換券を受け取る今回の設計には、オンライン専用が合致します。

### 5. IIS に配置する

発行フォルダの中身と `launch-test.html` を、IIS サイトの `/smartclient/` に配置します。

**IIS の MIME タイプ設定が必要です。** 既定では `.application` などが未登録で、そのままだと 404 になります。IIS マネージャーの「MIME の種類」で追加してください（既にあれば不要）。

| 拡張子 | MIME タイプ |
|---|---|
| `.application` | `application/x-ms-application` |
| `.manifest` | `application/manifest` |
| `.deploy` | `application/octet-stream` |

> **この段階では Shibboleth SP の保護は掛けません。** まず素の状態で通してから、フェーズ2で保護範囲を設計します。

### 6. ブラウザから起動して確認する

```
https://plmdev.plm-lab.local/smartclient/launch-test.html
```

を開き、(1)〜(3) のリンクを順に試します。

## 判定基準

| 確認項目 | 期待する結果 |
|---|---|
| (1) 固定の引換券 | アプリが起動し `ticket = TESTTICKET-12345` と表示される |
| (2) ランダムな引換券 | **毎回異なる値**が表示される（キャッシュされない） |
| (3) 引換券なし | アプリが起動し「受け取れませんでした」と表示（**落ちない**） |

**(2) が特に重要**です。本番では引換券は毎回変わるため、初回の値がキャッシュされて使い回されると設計が成立しません。

アプリ画面の「診断」欄に、失敗時の手がかりが出るようにしてあります。

## うまくいかない場合

| 症状 | 原因の候補 | 対処 |
|---|---|---|
| ビルドできない（`ApplicationDeployment` が見つからない） | `System.Deployment` 参照の追加漏れ | 手順2を実施 |
| リンクが 404 | MIME タイプ未登録 | 手順5の MIME 設定を追加 |
| アプリは起動するが `ActivationUri` が空 | `TrustUrlParameters` が未設定 | 「マニフェスト」のチェックを入れて**再発行** |
| `ActivationUri` にクエリが無い | ブラウザが「ダウンロードしてから実行」している | 下記の代替案へ |
| そもそも起動せずファイルが保存される | ブラウザの ClickOnce 対応 | Edge の ClickOnce 設定を確認、または代替案へ |
| 「発行元を確認できません」の警告 | VS が生成した仮の署名証明書 | 検証段階では続行して可（フェーズ2以降で内部CA署名を検討） |
| HTTPS で証明書エラー | ルート CA 未信頼 | SSO 構築時に導入した `PLM-Lab Root CA` が信頼されているか確認 |

### 代替案（ClickOnce でパラメータが渡せなかった場合）

いずれも実績のある手法です。**フェーズ1で判明すれば手戻りは最小**で済みます。

- **代替案A：カスタム URI スキーム** … アプリが `plmclient://` をレジストリに登録し、Web ページから `plmclient://ticket=XXXX` へ遷移させる。ClickOnce のパラメータ制約を完全に回避できるが、アプリのインストールが前提になる。
- **代替案B：ループバック方式** … SmartClient がローカルポートで待ち受け、ブラウザが `http://127.0.0.1:PORT/?ticket=XXXX` にリダイレクトして引換券を渡す。OAuth 2.0 のネイティブアプリ標準（RFC 8252）と同じ仕組みで、**最も本番向きで堅牢**。実装量は少し増える。
- **代替案C：引換券を含む小さな設定ファイルを配布** … 独自拡張子のファイルをダウンロードさせ、ファイル関連付けで起動する。設定はやや煩雑。

## このフェーズが通ったら次にやること

**フェーズ2：IIS のサイト構成整備**に進みます。4.8 に統一したことで、当初の2アプリ構成が**1アプリに簡素化**できます。

- HTTPS サイト（`plmdev.plm-lab.local`）に、**WebForms と Web API 2 を同居させた単一アプリ**を配置
- **Shibboleth SP の保護をパス単位で分ける**：`/`（.aspx）は保護、`/api`（トークンサービス）と `/smartclient`（ClickOnce）は保護から外す
- `Request.ServerVariables["REMOTE_USER"]` が取得できることの確認
- 開発時に REMOTE_USER を疑似的に与えるモードの用意（SP は IIS Express では動かないため）

保護範囲の設計が、この構成全体の土台になります。
